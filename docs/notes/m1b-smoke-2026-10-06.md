## Haiku: 400 on every turn

Every turn failed with `400 tools.4.custom: For 'object' type, 'additionalProperties' must be
explicitly set to false`. The stored request blob (`976a2ab9...`, first turn of a002) lists the
tools as 0 `guess`, 1 `my_status`, 2 `collective_status`, 3 `read_board`, 4 `post`, 5 `end_turn`.
Tool 4 was:

```json
{"name": "post", "parameters": {"additionalProperties": false, "required": ["text"], "type": "object",
 "properties": {"channel": {"enum": ["main"], "type": "string"}, "fields": {"type": "object"}, "text": {"type": "string"}}}}
```

The adapter sent a tool `strict: true` whenever its top level had `additionalProperties: false`
and a `required` list. That made `guess` and `post` strict; strict mode requires
`additionalProperties: false` on every object at any depth, and `post.fields` was an open
`{"type": "object"}`. `my_status`, `collective_status`, `read_board` and `end_turn` had no
`required` list, so they were sent non-strict and not rejected. The error is about the nested
`fields` object, not the missing top-level keys.

Probe accuracy 0.75 with zero actions: each failing turn had already appended the round's
observation (candidates and the agent's crop) to the agent's memory before the inference call
failed, so the probe asked about a context that held the crop. Three of four agents named the
true flag G from their crop alone (a003 said F at 0.35 confidence; in round 3 a001 switched to C at
0.95). This is the per-agent prior a swarm has to beat; it is high on this world configuration
(8 candidates, 3x4 crops), which matters when picking world difficulty for experiments.

## Qwen3.5-9B: thinking ate the token budget

All 7 `no_tool` turns have the same response: `finish_reason: "length"`,
`completion_tokens: 1024` (= `max_tokens`), `text: ""`, no tool calls. The 5 turns that worked
used 681 to 996 completion tokens, also with empty text, then called `guess` and `end_turn`
natively. The model reasons before answering (Qwen3 thinking is on by default) and the reasoning
is not returned in `content` (`reasoning_tokens` reported as 0, so DeepInfra does not split it out
in usage either); at 1024 tokens it usually ran out before reaching the answer. No response
contained a tool call written as text (`guess(...)`, a JSON call or `<tool_call>`): the text
fallback would not have rescued any of these turns.

Probes, 9 of 12 failed:

- 7 are `length` with empty text;
- 1 is `length` with visible reasoning prose that never got to an answer: `"Need to identify which
  candidate contains the 3x4 crop: ... Looking at G more carefully - if I take rows 5,6,7: ..."`;
- 1 is `length` truncated inside the answer: ``"\n\n```json\n{\"candidate\": \"C\", \""``;
- the 3 that parsed were plain JSON, for example `"\n\n{\"candidate\": \"C\", \"confidence\": 0.85}"`.

None contained `<think>` tags. Native tool calling itself works on this model through the HF
router (`finish_reason: "tool_calls"`, arguments parsed, 13/13 calls ok).

## Fixes (branch `fix-smoke`)

1. Tool schemas: `ToolSchema.normalized()` makes every object schema complete
   (`properties`, `required`, `additionalProperties: false`, recursively for objects that declare
   properties) and `strict_violations()` checks Anthropic's strict rules at every depth. World
   `@tool`s, status tools, board tools and `end_turn` are emitted normalised; `post` no longer
   advertises the free-form `fields` object (the executor still accepts it). The Anthropic adapter
   normalises before sending and sets `strict: true` only when there are no violations, so a
   free-form nested object now goes non-strict instead of failing the request. A test asserts
   every `RoundExecutor.schemas()` schema for FlagGame passes the strict check.
2. `LLMAgent(extra=...)` passes provider body fields on every request, probes included. The Qwen
   arm now sends `extra={"chat_template_kwargs": {"enable_thinking": False}}`, which DeepInfra
   documents for Qwen3.5-9B (the HF router forwards the body). The OpenAI-compatible adapter merges
   `extra` into the body top level (and flattens an `extra_body` key).
3. `LLMAgent` default `max_tokens` is now 2048 (the smoke script keeps 1024 explicitly, which is
   enough with thinking off and keeps the Haiku estimate under its ceiling). Each turn's
   `turn_ended.usage` carries `finish_reasons` and `notes`; `"length"` marks a response that hit
   `max_tokens`.
4. `LLMAgent(text_tool_fallback=True)` (opt-in, experimental condition) executes tool calls a model
   writes as text (`<tool_call>` blocks, `guess(candidate="B")`, JSON call lists), logged and noted
   as `text_tool_fallback:<n>`. It would not have helped this smoke; it exists for models that do
   write calls in text.
5. `BeliefProbe.parse` strips reasoning (closed, dangling or unterminated `<think>`), takes the
   first JSON object anywhere, accepts `answer`/`guess`/`flag` for `candidate`, recovers a
   `"candidate": "C"` pair from truncated JSON (`partial: true`, which would have rescued the
   fenced, truncated answer above), and matches the name case-insensitively against the
   candidates read from the agent's latest FlagGame observation (`Probe.candidates_from_context`,
   passed to `parse` by the runner).
6. `tools/real_smoke.py` adds a `haiku-json` arm (2 agents x 2 rounds, `tool_protocol="json"`,
   ceiling $0.20) and refuses to run if any estimate exceeds its ceiling or the total reaches
   $1.00. New estimate: haiku $0.378, qwen $0.029, haiku-json $0.126, total $0.533.

Open: the OpenAI-compatible adapter ignores `message.reasoning_content`, so a reasoning model's
hidden reasoning is neither stored nor counted separately; if we want to study it, `ChatResponse`
needs a field for it.
