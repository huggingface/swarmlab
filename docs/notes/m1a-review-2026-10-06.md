# M1a review: swarmlab @ a45e746

**What I ran.** `pytest -q`: 182 passed (24 s). CLI `run examples/flaggame_m1a.yaml --seed 11 --json`: broadcast accuracy 1.0, gossip 0.8125. All three `examples/0*.py` ran. Repro scripts are in `review/adv/`.

## A. Correctness and validity bugs

**A1. The Flag Game can be solved from the observation alone.** Blocks M1b. `world/flaggame.py:245-262`: the rival is the truth with about 14 cells recoloured, and the distractors are clean structured flags. So the nearest pair of candidates (by Hamming distance) is always {truth, rival}, and the cleaner flag of the pair is the truth. A zero-evidence rule built on that chose the truth in **100%** of 1000 seeds (chance is 12.5%). An LLM may notice the noisy twin. If it does, crops and communication become irrelevant and M1b acceptance (5) fails. The word-based Enumerator oracle cannot detect this. Fix: make the rival structured too, and/or add near-twin distractor pairs.

**A2. Subclasses inherit `entry_point`, so their identity is aliased.** Blocks M1b. `base.py:65`: `class Louder(EvidenceAggregator)` and `class BigFlag(FlagGame)` serialise as the parent type. As a result:
- `spec_hash` cannot tell them apart from the parent.
- `from_spec`, `from_yaml`, `Run.load().resume()` and CLI fork silently rebuild the **parent** class.

Repro: `adv/spectest.py`. Only `tests/helpers.py:22` avoids this, by setting `entry_point = None` by hand. Fix: honour `entry_point` only when it is in `cls.__dict__`.

**A3. Participants cannot hold a provider client or receive shared services.** Blocks M1b design. Per-agent `copy.deepcopy` (`runner.py:239`) plus the pickle-of-`__dict__` snapshot (`base.py:18-20`) means:
- `deepcopy(httpx.AsyncClient())` raises `TypeError: cannot pickle '_thread.RLock'`, and a participant holding a `threading.Lock` crashes `run()`.
- `bind(agent, rng)` has no way to pass a shared provider, gate or ledger. Per-agent copies would also defeat the fair gate and the hard ceiling.

The contract needs this decided first, e.g. `bind(..., services)` or a runner-owned `tools.infer`, with services excluded from snapshots.

**A4. `end_turn` loses usage or misreports the yield.** Blocks M1b. `runner.py:559-566`: `EndTurn` propagates out of `turn()`, so the returned `TurnUsage` is lost and `usage == {}`. If the participant catches `EndTurn` and returns its usage, the turn is logged as `no_tool`. Repro: a000 → `end_turn {}`, a001 → `no_tool {tokens…}`.

**A5. The crop position reaches the agent.** Blocks M1b. `flaggame.py:283` stores `crop_y`/`crop_x` in `Observation.private`. `view.py:18` calls that field "evaluator-only", yet `runner.py:554` passes it to the participant. The contract says the position is withheld. In 1000 seeds, knowing it resolves 39% of crops that are otherwise ambiguous.

**A6. `comm.hops` overcounts.** Blocks M2 only. `metrics/comm.py:112` counts same-round reads even when the read came after the post in the turn. Repro: a participant that posts then reads (3 agents, 5 rounds) gives `[1,2,3,4,5]`; the correct values are `[1,1,2,3,4]`. Also, the value is a cumulative maximum paired with a per-round "turns" denominator, which is meaningless for it.

## B. Contract deviations

**B1. The executor is not bound to an agent.** Fix before M1b. `executor.py:191` and `runner.py:560`: the participant receives the `RoundExecutor` itself, including `.world`, and `call()` accepts any agent id. Repro: in a000's turn, `tools.call("a001", "guess", {"candidate": tools.world.truth})` was committed and logged as a001's action. This violates DESIGN Integrity. Fix: pass a per-agent facade.

**B2. Belief denominators differ between the documents.** Decide before M1b. `metrics/belief.py:43` divides by agents that have guessed. That matches INTERFACE §14, but DESIGN §10 says to "count none explicitly". `belief.accuracy` (1/1 = 1.0) also differs from `score()["accuracy"]` (1/3, `flaggame.py:288`). LLM agents that never guess will inflate consensus and accuracy.

**B3. Operational events have no path.** All turn events are buffered until `gather` returns (`runner.py:586-592`). So `inference_attempt` cannot be logged before the call, and spend from an aborted round is lost.

**B4. Minor deviations:**
- The pending post id `tmp-a002-0` is never linked to the real `p0001-0001` (`executor.py:262`).
- `Experiment.options` is a `dict`.
- `allowlist` is not wired.
- Status tools ignore the agent's own buffered writes (DESIGN §2.3).

## C. Friction for scientists

The hypothesis test passes: topology, a `Policy`, a new `World` or a new `Participant` each needs one small class and no runner, log or snapshot code. The friction points:

1. **Run ids ignore configuration.** `experiment.py:95`: the same name and seed under a different commit mode or topology raises `FileExistsError`. That is safe, but awkward.
2. **`run()` fails inside notebooks.** It calls `asyncio.run` (`runner.py:335`), which raises inside a running loop (Jupyter). It also leaves a dir behind, after which a rerun raises `FileExistsError`.
3. **Spec round-trips lose information.** A nested plugin param comes back from `from_spec` as a dict: `Strategy(5)` → `dict`. Attributes set after construction do not change `spec_hash`.
4. **Class-level mutable state is unprotected.** It is shared across agents and runs and never snapshotted. Two `run(seed=1)` calls gave different guesses.
5. **Forks cannot change options.** They always inherit the parent's options (`runner.py:448`), so the seed and commit mode cannot change, and replicate forks with fresh sampling are impossible.
6. **Metric limits.** Metric names must be unique (no second polarization threshold), belief metrics are hard-coded to `guess`/`candidate`, and `Metric.from_fn` does not survive `from_spec`.

## D. Fine, but worth knowing

1. **Determinism holds.** I used 3 processes with different `PYTHONHASHSEED`, concurrency 1 vs 32, OS-random async sleeps, gossip and a delay policy. The logical views were identical apart from `run_started`, and the snapshots were byte-identical. Caveat: `concurrency` is in `RunSpec`, so it changes `spec_hash`.
2. **Recovery holds.** 13 random SIGKILLs plus 7 targeted ones (after the snapshot write, after `round_committed`, mid-commit) all resumed equal to the reference. Gap: a kill between the `run_started` append and the first `run.json` (`runner.py:327-334`) leaves a dir that can be neither resumed nor rerun.
3. **Fork holds.** The prefix and `snapshots/000006.json` were byte-identical; edited forks and a fork of a fork worked.
4. **Visibility rules hold.** Withholding, delay and rewrite policies worked. `round_end` read lag was ≥ 1; `immediate` gave lags of 0 or 1 and same-round `collective_status` counts (0, 1, 2, 3).
5. **fsync cost.** Every blob is fsynced every round, which dominates wall time. This is a concern at hundreds of agents.
6. **The viewer embeds the truth.** It is in the page JSON, hidden only by a checkbox. Never expose `view.html` or the run dir to agents.
7. **Run identity covers only swarmlab.** `git_identity` (`runner.py:245`) records swarmlab's own repo, not the experiment script.
8. **Two minor quirks.**
   - A policy that returns `round` under `round_end` is labelled eligible in r but can only be read in r+1 (`medium/board.py:225`).
   - `resume()` of a run whose `run_ended` was logged but whose `run.json` was not rewritten stays `running` (`runner.py:350-353`).

## Verdict

**Fix first.** The execution core is solid: phase-commit isolation, seeded ordering, the log, snapshots, recovery and fork all survived adversarial testing. But A1 makes the Flag Game solvable by inspection, so LLM results on it would be uninterpretable. A2 and A5 break identity and information hiding. A3, A4 and B3 will be hit by the first real participant and provider. Before M1b:
- Fix A1, A2, A4, A5 and B1.
- Settle A3, B2 and B3 in INTERFACE.md.

A6 and the C items can wait for M2.
