# M6 results (written overnight 2026-10-07/08; the real-flag section is updated when the 10-seed grid finishes)

## 1. Real flags, paper-faithful (`experiments/m6_flag_paper.yaml`, Gemma 4 26B-A4B via HF router → DeepInfra)

### Pilot, seed 1 only (17:37–17:56 UTC, nine runs, $0.35 total)
Hidden flag was **Peru** in every arm (one seed → one flag; the paper draws a country per trial). Accuracy was 0 in eight arms and 0.10 in pairwise-128. Every agent answered Indonesia, Poland or Austria (red-and-white horizontal flags); nobody answered Peru (the only red-and-white vertical flag in the list). So the model reads the crop's colours and uses flag knowledge, but does not use stripe orientation; with Peru as the target the task is nearly unwinnable for it. The manager arms were additionally broken by a harness bug: members answered `{"answer": ...}` instead of `{"country": ...}` and the report parser rejected 146 of their replies, so the manager received nothing (fixed in `d6dfe3a`: the parser now accepts answer-key synonyms). Those three runs are kept under `runs/m6paper/_seed1_manager_prefix/`.

Paper (GPT-4o, 40 seeds, Table 3) for comparison: pairwise correct 50–53% at N=4 and N=16, 38–41% at N=128; wrong 26–34% at N=4, 0–11% at N=16, 0% at N=128; polarized 13–24% / 18–45% / 57–60%. Manager accuracy 0.48 (GPT-4o) / 0.57 (GPT-5.4).

Reading:
- **The paper's central pattern reproduces on a far weaker, open model.** Under pairwise gossip, wrong consensus vanishes as N grows (0.20 → 0.00 → 0.00) and polarization takes over (0.50–0.60), with fragmentation appearing at N=128. The absolute correct-consensus rate is lower than the paper's (0.20–0.30 vs 0.5), which is the model gap: Gemma 4 26B-A4B reads crop colours but not stripe orientation (pilot: Peru → Poland/Austria/Indonesia).
- **Broadcast herds.** 10–30% of runs lock onto a wrong flag, and correct consensus is higher at small N (0.40) than pairwise, i.e. broadcast is faster and more often wrong, the cascade-paper dynamic.
- **A blind manager is a single point of failure for this model:** its decision ends in a wrong consensus 60–70% of the time; manager accuracy 0.30–0.40 vs the paper's 0.48–0.57.
- **Cost:** the whole 90-run grid cost $3.95 and ran in about two hours of wall time with four runs in parallel; the equivalent of the paper's 40-seed sweep would be about $16 per model on this provider.

Caveats: one seed per flag per arm (ten seeds, nine flags); `rounds_per_agent: 10` is a guess at the paper's κ; the manager arms use the paper's m=1 reports; three seed-1 manager runs were redone after the report-key bug. Full report: `m6-flag-paper-report-2026-10-08.md`. Run dirs: `/data/workspaces/ultra-harness/runs/m6paper/`.

## 3. Framework notes from the night
- A one-seed grid is a one-flag grid: `seeds` must cover several flags in this world. Consider a `FlagGame(flag_per_arm_seed=...)` or documenting that the hidden flag derives from the seed.
- Report-JSON key drift (`answer`/`guess`) silently zeroed a protocol arm; fixed, and the health section now shows it (`report_json:failed` notes).
- The experiment-level cap counts in-flight reservations; with `--parallel`, the last large arms can be refused even when actual spend is far below the cap. Either lower the per-arm hard caps or run large arms first.
