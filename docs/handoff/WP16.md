## The three protocols as specs

```yaml
# broadcast
medium: { topology: { type: broadcast } }

# gossip: each agent's posts reach k=1 partner per round, redrawn every round
medium: { topology: { type: gossip, params: { k: 1 } } }

# manager: a000 is blind (no crop, no guess tool), every member reports only to a000,
# a000's posts reach every member; N counts a000
world: { type: flaggame, params: { blind_agents: 1 } }
medium: { topology: { type: star, params: { center: a000 } } }
participants:
  - { type: llm, role: manager, params: *llm }
  - { type: llm, count: 15, params: *llm }
```

Gossip semantics, confirmed against the code: `Gossip(k=1)` computes once per round, from the
round's topology rng (`derive(seed, "topology", round)`), one partner per author drawn from the
other live agents; all of that author's posts that round go to that partner only. So in every
round each speaker has exactly one listener. It is directed and not a matching: a listener may hear
several speakers (or none) in a round, and A->B does not imply B->A. There is no separate
`Pairwise` class; `gossip` with `k: 1` is the paper's pairwise protocol (now documented in the
module docstring and tested in `test_gossip_k1_is_one_listener_per_speaker`).

## Blind agents (FlagGame)

- `blind_agents: 1` (an int: the first n agents by index) or `[a003, a007]` (ids). Both params
  are left out of `spec()` while unset (`None`, `[]`, `0`; `blind_may_guess: false`), so every
  existing spec hash is unchanged.
- Crops are still drawn for every agent and then dropped for the blind, so candidates, truth and
  the other agents' crops are the same as in the arm without blind agents (the bc/gossip arm with
  the same seed). `test_arms_share_the_world_draw` checks this on the m6 arms.
- Observation: the candidates as usual, then (text) a blank line and `You have no crop of your
  own; rely on what others report.`, or (image) the framing line without "your crop follows" and
  that sentence as the last text part. `private` is `{}`. `parse_observation` skips the line.
- Tools: no `guess` (the executor asks `world.allows_tool`); the world also refuses the guess
  itself (`blind agents may not guess`). `blind_may_guess: true` restores the tool; such guesses
  are still not scored.
- Scoring: `score()["accuracy"]` and `n_guessed` are over sighted agents; `n_blind` is added when
  there are blind agents. Every `belief.*` metric (world- and probe-sourced) leaves them out of the
  numerator and denominator via `excluded_from_belief()` (the runner's `set_agents`), so
  `belief.accuracy` still equals `score()["accuracy"]`. `comm.*` metrics still count the manager.
  `verify()["crops"]` omits them; `verify()["blind"]` lists them.
- Task text: `description_for(agent)` gives a blind agent its own description ("Other agents
  each privately see a 3x4 crop ... You have no crop of your own: you rely on what the others
  report. You do not record guesses yourself."). Sighted agents get `description()` plus one
  sentence when blind agents exist: "Some agents have no crop of their own (their observation
  says so) and rely on what others report."
- `patch_private` / `crop_overrides` on a blind agent, an unknown id, or a blind set covering
  every agent are `ValueError`s.

## Star and the manager role

`Star(center)`: a member's post is delivered only to the center (to nobody if the center is not
live); the center's posts to every live member. No channels or permissions: deliveries only.
`manager` role: `may_act: false`, `channels_read`/`channels_write` null (all), `prompt_append`:

> Your job: you are the manager. You have no evidence of your own and you never act in the world
> yourself; every other agent reports to you and only you, and your posts are the only thing they
> hear. Each round, read the board to collect the members' reports, then post a single summary that
> states which candidate the evidence supports and why, citing the reported evidence (or, if the
> evidence does not yet single one out, which candidates remain and what would tell them apart).

## Decisions

- **N counts every agent.** `manager-N` has N agents: a000 is the blind manager and a001..
  a{N-1} are the N-1 members with crops. Accuracy and belief metrics are over the N-1 members,
  bc/gossip over all N, so at N=4 the manager arm has one fewer evidence holder (3 crops vs 4).
  This is the paper's framing (the manager is a participant who sees no crop); the alternative
  (N members + 1 manager) would need `count: N` members and changes only the YAML.
- **`collective_status` is off in every m6 arm** (`status_tools: [my_status]`). It reports the
  swarm-wide guess counts to every agent, a global channel that bypasses the gossip and star
  topologies; leaving it on would blur the protocol comparison. It is off in bc arms too so the
  arms differ only in topology (and the blind manager).
- **Members are not told about the manager.** Their prompt is the bc prompt plus one sentence
  ("Some agents have no crop of their own ... rely on what others report."); they learn the
  structure from what reaches them (only a000's posts). bc/gossip arms do not explain their
  topology either. To tell members explicitly, add a `member` role with a `prompt_append`.
- **Blind agents are a world parameter, not a role**: the evidence is the world's business (no
  crop), the permission (`guess`) follows from it through `World.allows_tool`, so a blind agent
  needs no role and a manager role works without blindness (`may_act: false` alone also blocks
  `guess`). The manager arm uses both.
- **Default `blind_agents=None`** rather than a mutable `[]` default; `[]`, `0` and `None` are
  equivalent and all stay out of the spec.
- **Belief populations**: the runner filters only metrics with `belief_population = True`
  (`belief.*`); `comm.*` keep every live agent, so the manager's reads and posts count in
  `comm.read_rate`/`comm.post_rate`.
- **`description_for`** (a new world hook) rather than conditional text in `description()`: the
  blind manager's task text must not tell it to use a crop or a `guess` tool it does not have.
  Worlds without the hook are unaffected (`describe()` falls back to `description()`).
- **`x-` top-level keys** (Docker Compose style) are dropped before validation so the memory
  setting can be a top-level anchor (`x-memory`) as asked; the spec also uses `x-llm`, `x-world`,
  `x-metrics` etc. to keep the nine arms short. They never reach a `RunSpec`.
- **Star with no channels**: it changes recipients only; a member that calls `read_board` sees
  the manager's posts. Star is centred on `a000` by default to match `blind_agents: 1`.
- **Smoke arms**: pricing pinned in the script from the router listing (DeepInfra 0.07 / 0.34,
  cached = input) like the Qwen arm; default memory (3 rounds, so window = full); budgets
  `soft 0.40 / hard 0.50 / measurement 0.10`. Worst-case estimates $0.030 each. The image
  overhead in the estimate is measured on a member (never the blind manager).
