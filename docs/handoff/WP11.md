### Runner hook (the only lines outside `llm.py`/`events.py`)

`swarmlab/runner.py`, `Runner._turn_inner`:

```python
        except Exception as e:  # noqa: BLE001 - any participant failure ends its turn as "error"
            kind = "error"
            error = getattr(e, "turn_error", None) or traceback.format_exc()  # M3a: e.g. context_limit
        ...
        drain = getattr(self.participants[agent], "drain_overflow", None)  # M3a §3 context limit
        for fields in drain() if callable(drain) else ():
            ex.note(OverflowEvent, agent, **fields)
```

The drain runs after the turn, whether it returned or raised, after the hard-ceiling check and
before `end_turn_event`, so `overflow` events sit in the agent's buffered turn events after its
tool events and before `turn_ended`. Any participant can report events this way by implementing
`drain_overflow()`, and any exception with a `turn_error` string sets `turn_ended.error` to that
string instead of a traceback. `executor.py` gains `note()`, so the runner does not reach into
`_ev`.

## Decisions where the contract was silent

- **Estimator.** `providers.preset(prefix)` is built once per agent (cached in `_estimator`,
  which is not snapshotted) and its `estimate_prompt_tokens(request)` is used on the exact request
  about to be sent (system, memory, tool schemas). If no preset can be built (for example `vllm`
  without a base url), the fallback is ceil(len(canonical JSON of messages+tools) / 4). A
  participant cannot see `Experiment.providers` overrides. That does not matter today because no
  provider overrides the base estimator.
- **When.** The check runs before every model request in the turn, not only the first one, so a
  long current round can trigger more drops mid-turn. Window trimming happens first, at turn
  start.
- **drop_oldest.** Whole memory entries are popped from the front until the estimate fits. The
  last entry (the current round) and the system prompt are never dropped. If they alone exceed the
  limit, the request is sent anyway, and an event is still logged with `tokens_after > limit`
  (and `dropped_rounds=0` when there was nothing to drop). In that case every request logs an
  event.
- **summarize.**
  - Entries are dropped until estimate + 400 (`SUMMARY_MAX_TOKENS`, room for the note) fits.
    Then one `tools.infer(..., category="measurement")` call on `summary_model` is made: system
    `SUMMARY_SYSTEM` ("under 200 words", keeps beliefs, evidence and decisions), the dropped
    entries rendered as text, `max_tokens=400`, `temperature=0`, no tools.
  - The note is stored as the memory entry `{"round": last, "from_round": first, "summary": True,
    "messages": [assistant "[Summary of my earlier rounds a-b]\n..."]}` at the front. An earlier
    note is dropped first and so is folded into the next one, which means memory holds at most
    one note.
  - `dropped_rounds` counts real rounds, not notes.
  - `MeasurementBudgetReached` keeps the drop without a note and sets `detail="measurement_budget"`.
    `HardCeilingReached` propagates as usual.
- **Summary model.** This is a third kwarg, `summary_model`. Its default (None) means
  `anthropic:claude-haiku-4-5`, DESIGN's default cheap model. Note that it is *not* priced at
  `Experiment` construction (`participant_model` only looks at `model`). The gate resolves and
  prices it at call time. Follow-up: have `Experiment` price `summary_model` too (in
  `experiment.py`, which this package does not own).
- **fail_turn.** One `overflow` event is logged (`dropped_rounds=0`, `tokens_after == tokens_before`),
  then `ContextLimitExceeded` is raised, which gives `turn_ended(yield_kind="error",
  error="context_limit")`. No request is sent. Memory keeps the round's observation, so later
  turns keep failing unless a window makes room. That is the experimental condition, by design.
- **Spec hash.** All three kwargs are removed from `params` when `context_limit_tokens` is None.
  `summary_model` is also removed when it is None, so existing spec hashes do not change (tested).
- **Window interplay.** A summary note counts as one entry of the window.
- **Snapshot, resume, fork.** Dropped messages are gone from `self.rounds`, so snapshots and
  `probe_context()` show the trimmed memory, and the note persists. The summary call is cached
  like every other call, so resume and replay never re-pay it.

## Tests (`tests/test_context_limit.py`)

- **params:** keys appear in params only when set, the spec hash is unchanged without a limit, and
  constructor validation works.
- **No overflow events when unset:** an unreached limit gives the same logical log.
- **Acceptance 6, drop_oldest:** limit 1300 over 6 rounds. Overflows are logged, the run reaches
  `max_rounds`, every sent request fits, and the snapshot holds only the kept rounds.
- **drop_oldest with limit 1:** the system prompt and the current round always stay, there is one
  event per request, and the reader still guesses every turn.
- **summarize:** exactly one measurement call per overflow (both provider requests and
  `inference_attempt(category="measurement")` are counted). The note is first in memory, is an
  assistant message, folds the earlier note in, sits right after the system prompt in the next
  request, and shows up in `probe_context()` after restore. A measurement budget refusal gives
  `detail="measurement_budget"` and no note.
- **Acceptance 6, fail_turn:** rounds 2 to 4 end with `yield_kind="error"`, `error="context_limit"`,
  0 calls, and no request sent.
- **Window plus limit:** with `window_rounds=2` there are no overflows. With `window_rounds=3`
  there is one dropped round per request from round 3.
- **Determinism and replay:** for each policy, two runs give identical logical logs, and
  `Run.load` (replay, zero provider calls) reproduces the overflow events, metrics and score.
- **Resume:** a crash mid-round 5 followed by resume reproduces the reference run's logical log
  and its overflow events (for drop_oldest and summarize). The round-4 snapshot holds the trimmed
  memory (with the note under summarize).

## Notes

- This is a pre-existing issue, not caused by this package. After `tests.test_recovery._truncate_mid_round` on a run that had *finished*,
  resume produces `budget` events whose spend differs from a clean run's. That is because
  `run.json`'s ledger still holds the finished run's totals. It happens without a context limit
  too. A real crash writes `run.json` only up to the last commit, so it should not be affected.
  The resume test compares everything except `budget` events.
- Another package is adding `LLMAgent.reconfigure(**kw)` in the same file. This package's changes
  are confined to the constructor tail, the "context limit" methods block, the module constants
  after `parse_text_tool_calls`, and two lines at the top of the loop in `turn()`. The contract's
  `reconfigure` list does not include `context_limit_tokens`/`overflow`.
