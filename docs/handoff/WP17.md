## Decisions where the contract was silent

- **Canvas/crop orientation**: `canvas=(width, height)` and `crop=(width, height)` ("24x16"), as
  overrides of the existing `width/height/crop_w/crop_h` (None by default, so specs are unchanged).
- **Real-flag order and truth**: candidates listed alphabetically (the definition order groups
  layouts and would leak structure); truth `rng.choice` over the 28; `rival` None.
- **names mode needs real flags** (ValueError otherwise).
- **Scheduler selection**: `options.scheduler` (plugin spec, absent = SeededShuffle).
  `OneSpeaker.listeners` is validated against `gossip.k` by the runner. Uniform speaker, the
  listener from the gossip draw (so never the speaker).
- **Probes under OneSpeaker** ask every live agent (order first, then the rest). The runner's
  `prepare_probe` hook gives an agent that has not spoken yet its observation (one
  `world.observe` call, whose only side effect is FlagGame's one-time "crop has changed" note) and
  feeds pending deliveries into received memory, so probes see the crop and the memory as in the
  paper (where the listener stores a message when it is sent).
- **Replay with partial orders**: `round_started.live` (logged only when the order is not a
  permutation of the live agents).
- **Push delivery never marked items read** (M1a decision, so an agent saw the oldest
  `push_limit` unread items every turn). `medium.push_consume: true` (opt-in) shows the newest
  `push_limit` unread items and marks all of them read; required for received memory.
- **Received memory format**: no `Round r.` line and no outcome lines (the paper has neither, and
  under OneSpeaker the round number leaks the step count); items shown as `- <post text>` without
  author ids; own answers as a JSON list; dedupe by a `(eligible_round, delivery_id)` watermark.
- **Broadcast arms use `memory: received`** with `memory_messages: N-1` (exactly the current
  round's other reports) and `answers_kept: 8` (own past decisions), which is the paper's
  broadcast memory; the contract's "window keeping own decisions" has no exact existing mode
  (`window` would replay whole earlier rounds, crops and reports included). `answers_kept` is new.
- **report_json**: JSON object anywhere in the reply; the first field is the answer; the answer is
  matched to the observation's allowed names; one retry on a missing answer or a rejected guess;
  native tool calls still accepted. The m6 arms use `tool_protocol: json`, so no tool schema reaches
  the model (the paper's agents had none). The probe question is the m=1 schema line
  (`Output JSON exactly: {"country":"<one allowed country>"}`), as the paper's probes differ from
  turns only in the schema line; `probe_context` omits the turn's schema line.
- **belief.state** population: live non-blind agents with a guess (or an answered probe);
  `value` is the class index 0..3 with the class in a new `metric.label` field (the metric value
  stays numeric for exports), plus `belief.state.<class>` one-hot series; `Metric.outputs()` is the
  multi-series hook.
- **stop_when** evaluates at probe rounds when the run has probes (any probe due), else every
  round; the streak is re-derived from logged metrics on resume. The m6 pairwise arms stop on
  `belief.consensus@probe:belief >= 1.0` (the consensus denominator is every live agent, so 1.0 is
  the paper's "full consensus of 100%").
- **Report endpoint**: manager arms -> the manager's final decision (a blind agent that guessed);
  else the last belief-probe round; else final committed guesses.
- **Manager arms**: N observers + the manager (N+1 agents); the built-in `manager` role is
  overridden to `may_act: true` with a JSON-compatible `prompt_append`, and the world sets
  `blind_may_guess: true`, so the manager's decision is recorded as a guess (not scored, out of
  belief denominators). Under `round_end` the manager decides on the previous round's reports.
  No probes in manager arms (the endpoint is the manager's answer).
- **Price pinning**: the YAML pins DeepInfra's Gemma price (2026-10-07 listing) in `providers:`
  so it validates and estimates offline.
- **rounds_per_agent** counts every participant and wins over a YAML `max_rounds` in the same
  options; an explicit `--max-rounds` wins over it.
