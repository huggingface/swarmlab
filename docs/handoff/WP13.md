## Using it

```python
from swarmlab import Board, Experiment
from swarmlab.participants.scripted import QueuePainter
from swarmlab.world.coloring import ColoringGrid

exp = Experiment(name="s0", world=ColoringGrid(height=8, width=8),
                 participants=[QueuePainter()] * 16,
                 medium=Board(registry=True, claim_policy="enforced"),
                 metrics=["coloring.coverage", "claims.violations", "claims.held"])
run = exp.run(seed=0, max_rounds=20)
```

```yaml
medium: {registry: true, claim_policy: enforced}   # or advisory (default); registry off by default
world: {type: coloring, params: {height: 8, width: 8, palette: 4,
        target_changes: [[5, [[0, 0, r]]]], worker_failures: [[3, [a000, a001]]]}}
```

Agent tools when `registry: true`: `registry_get(key)`, `registry_put(key, value)`,
`registry_cas(key, expected_version, value)`, `registry_acquire(key, ttl_rounds)`,
`registry_release(key)`. A world opts into claims by overriding
`World.claim_key(agent, action) -> str | None`.

## Decisions where the design was silent

- **Commit order**: posts, registry writes, world actions. A claim acquired this round protects
  an action this round. Registry ops are applied in the round's seeded agent order, each agent's
  in call order, so the seeded-earlier acquirer wins; the loser gets `ok=False, error="held"` with
  the holder and expiry.
- **TTL**: a claim acquired in round r with `ttl_rounds=k` is live in rounds r .. r+k-1
  (`expires_round = r + k - 1`). The owner may re-acquire to renew. `release` by anyone but the
  live owner fails with `not_owner`.
- **Versions** count every successful write to the key, including acquire and release. CAS on a
  missing key expects version 0. `put` is unconditional (ownership does not guard values).
- **Values** are any JSON (at most 4000 chars of JSON). The tool schemas advertise a string,
  because a free-form value cannot be expressed under strict tool use; scripted participants may
  store objects. Keys are non-empty strings of at most 200 chars.
- **`get`** is never committed and writes no `registry` event (the tool call/return events
  record it). It shows round-start state plus the caller's own pending writes, applied tentatively,
  with `"pending": true`; owner/expiry show only live claims.
- **Outcomes**: registry outcomes are appended to the agent's next `View.outcomes` after its
  world-action outcomes, as `{"action_id": op_id, "tool": "registry_acquire", "accepted",
  "feedback": {key, version, owner, expires_round, error?}}`. Op ids are `g{round:04d}-{agent}-{n:02d}`.
- **Claim check and violations**: one `claim` event per world action with a key (only when the
  registry is on), before the `action_committed` events. `violation` means another agent held a
  live claim on the key, under either policy; under `enforced` those actions (and actions on keys
  nobody holds) are rejected with `feedback={"error": "not_claimed", "key", "owner"}` and never
  reach the world. `claims.violations` is cumulative (denominator: keyed actions so far);
  `claims.held` is the live claims after the round's commit (denominator: live agents).
- **Where the config lives**: `registry` and `claim_policy` are `MediumSpec` fields, and the
  `Board` constructor accepts and stores them so `Experiment.from_spec` (`Board(**medium)`) and
  `to_spec` (`MediumSpec(**board.spec()["params"])`) need no change. The runner builds the
  `Registry` and reads the board's policy. `enforced` without the registry is a `ValueError`.
  Neither field is serialised at its default, so earlier run specs, YAML documents and hashes
  are unchanged (tested).
- **Worker failures** go through the kill mechanism: at the start of round r the runner calls
  `world.begin_round(r)`, then removes `world.killed_at(r)` (those still live) with
  `Ops(runner, "worker_failures", r).kill(...)`, which logs one `intervention` event per agent
  (`intervention="worker_failures"`, `op="kill"`) before `round_started`. The agents take no
  turn from round r on and leave metric denominators; their claims lapse by TTL.
- **Target changes** apply in `begin_round(r)`, before anyone observes round r. The metrics apply
  the same changes on `round_started` from the truth (`verify()["target_changes"]`).
- **Paint limit**: `paints_per_round` (default 1) is enforced at commit (`error="paint_limit"`),
  because `validate` cannot see the agent's other buffered actions. Without a limit a single
  row-major agent would paint the whole grid in one round.
- **Conflict rule**: last writer in commit order wins; earlier writers of the same cell in the
  same commit batch get `accepted=True, feedback={"result": "overwritten"}` (others `"painted"`).
  Under immediate commit nothing is reported overwritten.
- **Paint accounting**: wrong = colour differs from the target; duplicate = the cell already
  matched and the paint repeats the target colour; useful = turns a non-matching cell into a
  matching one; wasted = every applied paint that is not useful. `score()` and the metrics fold
  the same rules and agree (replay checks it).
- **Status tools**: `my_status` gives `{"paints", "cells_mine"}`, `collective_status` gives
  `{"coverage", "cells_matching", "cells"}`. The target is public in the plain variant, so they
  carry nothing an agent could not compute itself.
- **Terminal**: coverage 1.0 with no target change scheduled after the current round.
- **Zones**: `zones=[rows, cols]` splits the grid into blocks and claim keys become
  `zone:<zx>,<zy>`. This is the minimal version of "crossed zones", and it is off by default.
- **Painters**: `RowMajorPainter` paints the first non-matching cell in row-major order.
  `QueuePainter(ttl_rounds=1, max_checks=4)` shuffles the non-matching cells with its rng, skips
  those whose `registry_get` shows another live owner (at most `max_checks` reads), then acquires
  and paints one cell in the same turn. `RandomPainter` paints a random cell with a random colour.
  Each paints `paints=1` cells per turn.
- **`fake:painter`**: registered as entry point `painter` in `swarmlab.fake_scripts` (in
  `world/coloring.py`, so `providers/fake.py` is untouched). Once per turn it paints a random
  non-matching cell (rng = f(request)) with its target colour, then `end_turn`. It does not use the
  registry.
- **Viewer**: unchanged. A coloring run gets `world = None`, so the page shows the generic
  committed-actions table (which includes the `registry` and `claim` events in the per-agent
  lists). I did not add a grid panel.
