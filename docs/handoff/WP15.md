## The image observation

Parts, in order: text `Candidate flags:\nCandidates A, B, C, D, E, F, G, H are shown as images in
that order (no label is drawn inside an image: the order is the labelling); your crop follows.
Each colour cell is 12x12 pixels in every image.`, eight candidate images (144×96 at the default
8x12 flag), text `Your crop:`, the crop image (48×36). With `image_text_hint=True`: a text part
`A:\n<rows>` after each candidate image and the crop rows after the crop image, so the text parts
joined with newlines parse exactly like a text-mode observation. A `patch_private` crop move adds
the text part `Your crop has changed.` at the end, once.

## Decisions where the contract was silent

- Framing text starts with the `Candidate flags:` line so the probe and the parsers find the
  observation the same way as in text mode; parsers skip prose before the first section (text
  mode never has any, so its behaviour is unchanged).
- `image_text_hint` is accepted and ignored in text mode (an arm grid can vary `modality` alone).
- The participant check runs in the runner at bind (fresh runs, round-0 forks), via a
  `check_participants` hook the runner calls when the world has it; scripted participants mark
  themselves with `reads_text_observation`; an `LLMAgent` is refused when its model resolves to
  the fake provider's `flaggame_reader` (other fake scripts and real models pass).
- Image token estimate: `ceil` of `w*h/750`; a part that is not a readable PNG keeps the old
  flat 1000 tokens (existing tests use non-PNG stand-ins).
- Preflight sends the full round-1 message only when the observation has images, so text-mode
  preflight requests are byte-identical to before.
- Exports: an image request is never inlined (even under 64 KiB) so the Parquet table does not
  carry base64; sessions carry a text label, not the image.
- `swarmlab estimate` does not model image tokens; the README says to use `--prompt-growth 730`
  or `--from` a finished run. The smoke script measures the overhead (image round message minus
  text round message, ~730 tokens) and adds it to the 3000-token planning prompt and as growth.
- `haiku-image` uses `max_calls=5` (the other Haiku arms 6) to keep that worst case under the
  $0.50 ceiling ($0.501 at 6); Haiku averaged 2.9 calls per turn in M2, so it should not bind.
  It is not in the default `--arms`, so the default three-arm total stays under the $1.00 cap.
- Visual-feature report: a post "mentions visual features" when it contains a colour word or a
  layout word (stripe, band, block, top, bottom, left, right, horizontal, vertical, ...); the
  report also counts posts that transcribe colour-letter rows.
