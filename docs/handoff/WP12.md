## Decisions where the contract was silent

- **Tables.** Key columns, then `seq` and `ts` of the row's first event. Joined families pair
  `turn_started/turn_ended`, `tool_called/tool_returned` (by `call_id`), `inference_attempt/
  inference_response` (by `call_id`, in order). `rounds` joins `round_started`, `budget`,
  `round_committed`, `snapshot` (an aborted round keeps `committed=false`). `run` keeps the last
  `run_ended` of a resumed run. A 13th family `other` holds every event type no family covers
  (`world_changed`, `budget_changed`, `overflow`, future types) as `type` + `payload` JSON, so
  every logged event lands in exactly one table. The log is read as plain JSON, not through the
  typed union, so new event types export without code changes.
- **reads**: one row per delivery id, and one row with `delivery_id = null` for a read that
  returned nothing (the reading-behaviour analysis counts empty reads); `read_index` numbers the
  read events.
- **Inlining**: cells hold UTF-8 text up to 64 KiB, else `"sha256:<hash>"` (that blob is then
  guaranteed in `raw/blobs/`), null when the blob is missing; the hash column is always there.
- **raw/**: besides `events.jsonl`/`discarded.jsonl` the export carries `raw/run.json`,
  `raw/snapshots/`, `raw/artifacts/` and `raw/blobs/` (full mirror incl. `cache/` under 500 MB;
  above: snapshot blobs + oversize blobs only), because `Run.load` needs snapshots and snapshot
  blobs to check the score.
- **Sessions**: pi v3 exactly (header `version: 3`, `cwd: "runs/<run>"`, plus the Hub's `harness:
  "swarmlab"`; entries chained by `parentId`, ids = 8 hex of sha256(`run/agent/n`)). LLM
  conversations are rebuilt from request deltas (suffix/prefix overlap, so window memory works)
  + response blobs for assistant messages + the final snapshot's memory for the tail (unpickled
  with a loader that allows only builtins and `random.Random`); tool results missing from both
  (window memory) come from the matching `tool_returned` events, so every `toolCall` has a
  `toolResult`. Probe calls are excluded (they are in `probes`/`inference`). `usage.cost` has
  only `total` (the run does not split cost by token kind). `api` = `anthropic-messages` or
  `openai-completions`. Scripted agents: `Round r.` user message per turn, one assistant
  `toolCall` + `toolResult` per call, `provider: "scripted"`.
- **Publish**: repo default `<whoami>/<experiment>`; explicit `--repo` with several experiments
  is an error. Created private; `--public` flips an existing repo public; nothing flips it back.
  The `format:agent-traces` tag is present iff the repo is public (only reachable via
  `--public`). Idempotence by comparing local content with the remote tree (LFS sha256 or git
  blob sha1); `index.json` merges the remote index; card and index are deterministic; commits in
  chunks of 1000 files. Card `configs`: `sessions` (default) + one per table family. The card is
  generated from `index.json` alone, so `publish` and `view --publish` agree. A run dir's
  existing `view.html` is uploaded by `publish` too. Export is written into `<run_dir>/export`
  and reused when current (same log sha256 + schema).
- **fetch-published** rebuilds `<out>/<run_id>/` from `raw/`, puts the export (minus `raw/`)
  under `export/`, refuses a non-empty target unless `--force`. Publish errors exit 2.
- **report**: default title `swarmlab report` (`--title` to change; the shim passes the M2
  title). Round columns span 1..max last round.
- **prompts**: one agent (the first) per group of consecutive identical participant specs; seed
  defaults to the YAML's first seed; scripted groups are listed with a note; tools are the
  executor's schemas for that agent. The world/board/participant are built the way the runner
  does it, without the Runner (no run dir, no gate).
- **Skill install paths** (checked against the agents' docs): Claude Code
  `~/.claude/skills/swarmlab/`, Codex `~/.agents/skills/swarmlab/`, OpenCode
  `~/.config/opencode/skills/swarmlab/` (OpenCode also reads `~/.claude/skills/`).

## Notes for whoever is next

- `swarmlab report` uses `Run.load` (full replay) and the typed event log, so a run with an event
  type the installed code does not know is skipped there; `export` is tolerant.
- The Hub trace viewer only renders public repos; nobody has looked at a swarmlab session in it
  yet (all repos so far were private). Worth one check when a first public repo exists.
- Smoke at N=4 is done by writing a smoke arm (no CLI override for `count`); the skill says so.
